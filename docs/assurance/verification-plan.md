# Verification plan: which claim is answered by which test or benchmark

Wingbox makes claims on the first screen of its README and in its benchmark reports. This page lists them and says for each one where its number is written, which test class or benchmark answers it, and the command that reruns it.

Only claims and numbers that are already published in this repository are listed, each with the file it comes from. Nothing was measured for this page and no number is new. Where nothing in the repository answers a claim, the line says "not assessed".

## How to rerun

| What | Command | Needs |
|---|---|---|
| The whole test suite | `cat requirements.txt requirements/*.txt \| sort -u > /tmp/wingbox-requirements.txt`, then `uv run --no-project --with-requirements /tmp/wingbox-requirements.txt python -m unittest discover -s tests` ([AGENTS.md](../../AGENTS.md), section 2) | uv |
| One test class | the same, ending in `python -m unittest tests.<file>.<Class>` | uv |
| The benchmark tests that need no model, in a clean container, each result compared with the committed one | `docker build -f Dockerfile.benchmark -t wingbox-benchmark .`, then `docker run --rm wingbox-benchmark` (ends with `REPRODUCED`, or lists the result files that differ) | Docker, network for the public repositories |
| One benchmark without a container | the "Reproduce" section of its README, quoted in section 2 | see there |
| The suite on Linux, macOS and Windows with Python 3.11, 3.12 and 3.13 | `gh run list --workflow tests --branch main --limit 1` (the workflow `.github/workflows/tests.yml` runs on every push to `main` and every pull request that changes code) | the GitHub CLI |

Every requirement with the test that verifies it is in [requirements.md](requirements.md).

## 3. What keeps a published number from drifting

- The reports of impact, find usages, the comparison and PHP equal the output of their scripts on the committed result files: `tests/test_benchmark_report.py::BenchmarkReportTest`.
- The two summary tables of the README hold only numbers of those reports: `tests/test_readme_numbers.py::ReadmeNumbersTest`.
- `Dockerfile.benchmark` and `benchmarks/php/Dockerfile.php` rerun the tests that need no model and compare every result file with the committed one.
- A new or changed benchmark number is shown to the maintainer before it is published ([AGENTS.md](../../AGENTS.md), section 6.5).

## 4. Planned, not done: missed edges per language

- What would be counted: for each language, the edges the reference requires and the graph does not have, each with its cause (a file left out of the graph, a form the parser does not follow, a name it could not decide), next to the wrong and missing totals the edge tests publish today.
- On which corpus: the seven corpora of `benchmarks/impact`, Test 3 (TypeScript, Rust, Python) and the three of `benchmarks/php`, Test 2, at their pinned commits; C#, Java, Go, Ruby, Dart and Pascal first need a corpus and a reference that shares no code with Wingbox.
- By which script: `benchmarks/impact/edge_test.py` and `benchmarks/php/tools/verify.py`, which already write every missing edge per corpus to `results/edges.json`; the count by cause is the part to add. The result is published with the benchmark reports, after the maintainer has seen it.
